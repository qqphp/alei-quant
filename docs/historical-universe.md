# 历史证券池与回填

## 使用顺序

1. 数据中心填写行情采集的起止日期，先保证该区间的完整交易日历已入库。
2. “历史证券池”中检查区间覆盖，再“回填历史证券池”。只采缺少完整快照的交易日，仍走唯一 BaoStock 通道、请求预算和持久化检查点。
3. 指定交易日读取成员，支持代码/返回名称查询、分页和当日完整 CSV。缺少该日快照时返回错误，不借用当前或相邻日名单。
4. 区间每日快照齐全后，选择“按历史成员回填 A 股日线”。采用区间成员并集，包含后来退市的证券；类型按固定版本证券档案识别。缺档案仅允许有留存官方公告的精确代码分类，来源随任务保存；其它未知代码仍停止，不猜测类型。

“仅回填结束日 A 股名单”保留原有模式，明确只包含结束日成员。它不能代表整个区间的全市场覆盖。已有固定池双均线模型仍是固定用户池；历史快照入库本身不等于已实现动态全市场选股策略。

## 来源与时间限制

官方 [`query_all_stock(day)`](https://www.baostock.com/mainContent?file=StockBasicInfoAPI.md) 返回指定交易日证券代码、交易状态与名称；状态 1 为交易、0 为停牌。当天日线就绪前可以返回空，平台不把空返回发布成空名单。本文依据官网 POST 文档正文与真实采集核对。

**名称仅为来源回溯返回，不能当作当年的简称。** 实际查询 2023-01-03 返回 `sh.600190 / 退市锦港`，当前档案退市日期为 2025-07-25。页面保留该源值并注明限制，不据名称前缀判断当时 ST；回测风险警示仍用行情日期对应字段。没有另行建立完整历史更名序列，也不声称首次发布原版已恢复。

名称允许来源空值，页面显示“来源未提供名称”，CSV 保留空值，快照返回 `missing_name_count`。成员完整与字段质量分别披露，不借用当前档案补造历史返回。代码及交易状态仍必须有效；同码完全相同的重复行保留接收数量和重复计数，成员集合去重。同码名称或状态不同则整批停止并保存冲突原文。

2025-09-02 实际重查有 6934 个唯一成员，`sh.516480` 名称为空、状态为 0；完整分页/CSV/原始哈希一致，重复采集零新增修订，见 [真实名称质量证据](verification-universe-name-quality.json)。此前重复代码失败批次未保存具体重复行，后续唯一返回不能证明原重复是相同行。失败批次和后续缺名诊断均保留于 [来源记录](source-conflict-universe-20250902.json)。独立恢复副本的九种构造响应核对相同重复、冲突拒绝与空名保留，见 [机制证据](verification-universe-duplicates.json)，不作为真实市场重复行证明。

## 存储与版本

迁移 7 增加 `universe_snapshots`：每个完整批次保存日期和精确成员集合，与原始行修订、发布标记在同一事务提交。相同内容再次采集可以没有新行修订，但仍保留该次完整成员集合。

读取时先固定该日最后已发布快照，再按其成员和发布版本读取名称/状态。后来减少的成员不会从旧行重新出现；未发布批次不可见，旧版本保持原集合。市场覆盖统计和回填使用相同成员定义。原始修订表及其通用导出是行历史，不能代替某日完整快照。

旧库只迁移原始全部行确实保存在同一批次的完整快照，不从跨批残留行猜测成员。已有 2026-10-09 批次 46 的 7424 个成员满足条件。

## 接口

| 方法 | 用途 |
|---|---|
| `GET /api/universe?day=YYYY-MM-DD&version=...&q=...&page=...` | 当日固定快照分页；返回快照批次、数据版本及来源限制 |
| `GET /api/universe/export?day=...&version=...` | 按同一成员集合导出完整 CSV |
| `GET /api/universe/coverage?start=...&end=...` | 完整本地日历对照已发布快照，列出缺少的交易日 |
| `POST /api/universe/backfill` | 按 `start/end` 为缺少快照的交易日生成采集任务 |
| `POST /api/backfill`，`pool_mode=historical` | 要求全部快照齐全，再用历史成员并集生成行情任务 |

管理请求仍需本机来源及 `X-Stock-Local: 1`。查询页面只访问 PostgreSQL。
