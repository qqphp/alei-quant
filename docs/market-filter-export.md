# 保存筛选条件与导出

在市场行情展开“估值 / 行业筛选与排行”，填写条件并保存名称；选择已保存条件后，点击“导出已保存条件”，下载 UTF-8 JSON 文件。导出的是所选保存记录，修改输入后需要先保存新记录。已有条件不会因导出而改写。

文件的 `format` 为 `stock-alei-market-filter`，`format_version` 为 1；`name`、`config` 保存原始名称和全部条件，`source_id`、`saved_at` 记录来源身份与保存时间。`notes` 包含单位、筛选和排序口径。`config` 可作为现有保存 API 请求的条件对象；网页导入功能尚未提供，不应直接把未知格式当作回测配置。

| 条件 | 口径 |
|---|---|
| `q` | 代码或名称文字检索，通配符按字面处理 |
| `type` | 来源证券类型；空字符串不限制类型 |
| `industry` | 当前已入库行业名称完整匹配；空字符串不限制 |
| `exchange` | `sh` 上海、`sz` 深圳；空字符串不限制，按完整证券代码前缀匹配 |
| `status` | 当前档案 `1` 上市、`0` 退市；字符串原样保存，空字符串不限制，不是历史可交易状态 |
| `sort`、`direction` | 来源字段排序及方向；缺值置后，非代码排序同值按代码升序 |
| `watch_only`、`with_bars` | 当前本机自选及已有最新日线行情；布尔值原样保存 |
| `pe_min`、`pe_max`、`pb_min`、`pb_max` | PE/PB 来源比值，下限及上限均包含；`null` 不设该边界，0 与空值不同 |
| `amount_min` | 最新日线成交额下限，人民币元，非负；`null` 不设限制 |

条件使用当前档案、当前行业、各证券最新已发布日线和本机当前自选。行情日期可能不同，有估值边界时来源缺值不按 0 筛选。导出不包含证券结果、自选成员副本、数据版本、历史股票池或回测配置；用同一条件在另一时间查询可能得到不同名单。

## 实际核验

- 数据库已有“示例：PE 0–20 / 成交额”的 12 个字段及浏览器新保存“示例：沪市退市 A 股”的 14 个字段，经真实 HTTP 下载全部相等，包括 0、`null` 和布尔值；名称与保存时间保持。旧记录不补写字段，网页读取时新条件默认空；新记录的状态 `"0"` 保持字符串。
- 不存在的 UUID 返回 404，非法 UUID 返回 422；所有核验仅读取主库，没有新增或删除筛选记录、没有调用 SDK。
- 先前浏览器未保存 PE 上限 21 不改变导出的 20；本轮实际下载新记录 964 字节，与 HTTP 文件 SHA256 相同。旧、新条件切换分别恢复空交易所/状态与 `sh`/`"0"`，页面控制台 error/warn 为空。新示例通过正常保存操作创建，验证脚本只读已有记录。证据 `verification-filter-export.json`、截图 `screenshots/filter-export.png`、`screenshots/exchange-status-filter.png`。
- 沪深交易所 × 全部/上市/退市六种组合的全部分页代码与原始档案集合一致；名称排序按数据库既有排序规则、同名按代码升序，重复查询稳定；非法交易所/状态返回 422。见 `verification-market-summary.json`。
- TypeScript 与生产构建通过，保留现有大包提示；本轮新增条件晚于 02:07 备份，需新版恢复覆盖。
