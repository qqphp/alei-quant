# 本机定时补跑

后台工作进程每分钟检查一次。停机期间不采集；重启后按已发布数据水位补齐之后的就绪交易日，不假定一次重启已完成所有数据。

## 水位与顺序

| 数据 | 水位 |
|---|---|
| 全市场 A 股/ETF 日线、每日复权因子 | 各接口成功发布批次的请求日期 |
| 证券池 | 完整、已发布快照的最大交易日期 |
| 四个主要指数日线 | 各指数已发布日线的最大日期 |
| 已选择的分钟数据 | 每个证券、每个频率的已发布最大交易日期 |

每轮从水位之后最早的交易日开始，最多安排 100 日；批次提交后下一轮接续，不取积压日期的末尾 100 日。证券池/指数共用按日任务，分钟按日合并需要补齐的证券/频率，分别有稳定任务键。重复调度不创建相同键的新任务，任务按实际插入时刻排队；补跑任务在一个数据库事务内写入，避免为每个日期反复建立连接。

首次没有水位，仅安排最新就绪交易日。ETF 不早于来源声明的 2026-01-05。可用日历来自已发布 PostgreSQL 数据；首轮先更新当前/次年日历。若需要较早年份，先采集对应日历，再使用区间回填。日期以上海时区判断，日线调度 17:40、因子 18:10、分钟 20:10；采集器仍独立校验来源就绪条件，成功空结果不能替代必要行情。

## 需要主动处理的情况

- 水位之前已存在的历史缺口不由最大日期自动发现，使用数据覆盖检查及指定区间回填。定时补跑不等于全历史已齐全。
- 失败/取消的任务保留原任务键、错误及检查点；数据中心按检查点重跑。排队/等待不代表失败，不因观察超时启动第二个通道。
- 调整证券或分钟频率后，新组合按自身水位计划；没有水位仍只从最新日开始，策略预热所需更早行情需单独回填。
- 财务、公司行动、周/月及宏观继续采用各自回看范围、披露日期和源就绪规则；这项补跑修复不证明首次发布原版或所有特殊事件已覆盖。
