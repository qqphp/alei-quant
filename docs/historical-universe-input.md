# 模型的历史证券池输入

## 清单与回调

在策略清单 `datasets` 中增加 `"universe"`。未声明时保持原来的行情/财务/账户输入，不自动增加历史池。对应频率的行情声明、预热和候选证券配置仍必须完整。

`context["universe"]` 包含完整指定日来源成员，不限于 `context["codes"]`：

| 字段 | 内容 |
|---|---|
| `day` / `available_at` | 来源查询交易日 / 平台保守就绪时刻，上海时间 17:30 |
| `source_batch` / `data_version` | 同日最后完整已发布快照 / 本次运行固定数据版本 |
| `members` / `data` | 完整成员数 / 按代码升序的 `{code, tradeStatus}` 数组 |
| `digest` / `digest_algorithm` | 日期、完整代码和源状态的 SHA256 / 明确的 UTF8 拼接算法 |
| `note` | 回溯来源、真实可交易和固定候选池限制 |

名称、当前档案类型和 ST 不进入这个输入。目标权重仍只接受运行配置 `codes` 内的代码；其它代码的行情不会因为池中有成员就自动加载。本次交付是完整来源池输入契约，固定候选池示例仍不能证明全市场无偏选股。

## 可见时钟与完整性

- 日线信号在当日 17:30，可读取当日池。分钟信号读取之前最新已达到 17:30 的交易日池，不能按当前 `valuation_date` 提前读取当日盘后池。
- 周/月信号按实际信号时刻选择此前最新已就绪的交易日池；周末、假期不生成虚构池。
- 固定版本中必要日期缺少完整快照、成员原行缺失或状态异常时失败；不借用当前名单或邻日名单填补。非日线还要求开始日前一个交易日快照。
- 重复采集零新增修订时，读取快照发布时的最后已知原行。后续发布/修改不进入指定旧版本。
- 每次回调获得独立数据副本。策略修改输入不影响缓存、以后信号或报告保存的来源依据。

引擎归档包含读取程序，运行清单保存数据版本和声明。报告 `signal_events.universe_ref` 引用完整快照批次，`universe_snapshots` 保存每个实际传入回调的来源元数据及摘要。没有将数千成员重复塞进每个信号记录；完整原值仍可按指定批次/版本从本机历史池接口导出。

## 实际来源限制

`query_all_stock(day)` 是当前查询返回的回溯数据，不能保证历史首次发布原版。实际 2023-01-03、2025-02-14 的来源池已经返回 `sz.302132 / tradeStatus=1`，但公司正式实施公告规定新代码 2025-02-17 才启用。旧代码 300114 在 02-17 仍为池成员，状态 0，并返回无价格末行。证据见 [代码变更核验](verification-code-change-marker.json)和[公司正式公告](https://static.cninfo.com.cn/finalpage/2025-02-15/1222544408.PDF)。

因此，平台按就绪时刻过滤的是来源池日期，**不能据此宣称成员/状态没有回溯修订或前视信息**。模型输入、报告警告、历史池页面和接口用途矩阵均披露此限制；行情、资产规则和交易时钟继续独立校验。平台没有手工改写来源成员或把缺价成员补成可交易行情。
