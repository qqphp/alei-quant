# 个人量化回测平台开发方案（审阅修订版）

日期：2026-10-10

## 目标

在本机提供一个中文网页平台，用于浏览 A 股基础数据和历史行情、管理本地 Python 策略，并在本地 PostgreSQL 数据上运行可复现的回测。第一版不包含实盘下单。

状态：2026-10-10 用户已明确授权实施，开发正在进行。本文保留总体规划和验收目标；实际环境、接口结果、已交付与未完成项见[实施记录](implementation-status.md)。官方文档及 SDK 声明不能代替实际数据完整度验证。

## 已确认信息与规划基线

- 使用入口为本机浏览器，面向个人单用户、Windows 本机环境；产品目标是尽量覆盖 BaoStock 官方文档列出的接口能力，按完整使用流程分阶段交付。
- 覆盖范围规划为 A 股、ETF 与指数，多周期 K 线、证券基础资料、行业、估值、复权与除权除息、财务及业绩报告、交易日历、指数成分和宏观数据；具体字段与历史范围以接口实际返回和官方说明为准。
- BaoStock 官方接口文档描述的是历史及盘后数据，没有承诺实时行情、逐笔、盘口、新闻全文或交易执行。若要补齐这些同花顺类能力，须另选数据源并确认授权；本方案先不假定使用其他来源。
- 用户已选择由平台寻找经典策略。首个模型确定为受信任本地 Python 包形式的双均线交叉示例，默认日线 10/30 日均线；包含登记、版本、参数、启用/停用和回测。后续用户模型按真实样例适配，不预设所有第三方回测框架或机器学习模型可直接兼容。
- PostgreSQL 地址为 `localhost:5432`，数据库名为 `stock_alei`。计划时用户说明尚未创建；获准后的初始化已完成，当前运行使用独立应用角色，具体状态见实施记录。后续迁移保留原数据。管理员凭据用于初始化，运行秘密放在本地配置中，不写入仓库或日志。
- 本文是开发方案，实施授权来自用户后续的明确确认，当前已获授权。部署到外部服务器、公开服务和实盘交易需要分别确认，不由本机开发授权推导。

市场覆盖以 BaoStock 实际支持的沪深证券为准，不把“A 股”理解为已经覆盖北交所或所有国内证券。指数用于展示和基准，不直接当作可买卖股票。ETF 的结算、公司行动和成交规则核验后再开放相应回测；证券档案中出现可转债/其它类型，也不等于其行情和回测已获支持。

首个可用回测以现金账户、沪深 A 股做多、日线为基线；分钟线与 ETF 回测按验证结果扩展。数据接口完整覆盖与全市场所有频率一次性全量入库是两个独立目标，后者按本机容量和请求预算决定。详细接口及资料局限见[数据能力研究笔记](research/baostock-data-capabilities.md)。

### 首个经典策略的确定规则

选用简单移动平均线（SMA）交叉策略，默认短期 10 日、长期 30 日，做多现金账户。短均线从不高于长均线变为高于时产生买入目标，从不低于变为低于时产生清仓目标；均线相等维持原目标。信号使用已结束行情，下一可用交易日开盘模拟执行。方法依据和完整契约见[经典双均线示例](classic-ma-strategy.md)。

示例另作明确约定：区间首日若短均线已高于长均线，则初始化持有目标；总目标仓位 95%，固定池各证券等额分配，无信号的份额保留现金。目标未变化不每日再平衡，未成交或部分成交也不自动追单。这些是平台示例政策，报告需展示，不能省略后仍称为完全相同的交叉策略。

预热需要至少覆盖长均线及前一时点的交叉比较，按清单允许的最大参数声明。当前股票日线模型允许长均线至 250 日，固定 251 根窗口；默认 10/30 不表示该模型只要求 31 根。历史较短的资产需要安装参数上限与预热匹配的独立版本，不能静默缩短已有模型的窗口、借用其它证券行情或伪造早期数据。参数是功能示例，不按历史收益选优。

## 建议架构

| 部分 | 建议 | 职责 |
|---|---|---|
| 网页 | Vue 3 + TypeScript + ECharts | 股票搜索/列表、基本资料、K 线与成交量、财务数据、回测配置和结果图表 |
| API | Python + FastAPI | 分页/区间查询、策略登记、回测任务提交/取消与结果读取；长任务返回任务 ID |
| 领域代码 | Python 模块 | BaoStock 适配器、数据校验、策略接口、回测撮合与指标计算 |
| 后台工作进程 | 独立 Python 进程 | 从 PostgreSQL 领取持久化任务；单一串行 BaoStock 采集通道；回测在独立进程中执行 |
| 数据库 | 本地 PostgreSQL | 市场/财务数据、数据修订与版本、任务状态、策略登记和回测结果；业务数据统一保存在本地库 |

API 和工作进程共享 Python 领域模块，避免 HTTP 请求里执行长时间回填或回测。任务状态由 PostgreSQL 管理，包含排队、运行、取消、失败和完成；采集按检查点续跑，回测中断后标记状态并允许按原运行清单重新执行。初期采用少量本机进程，不要求 Redis、Docker 或额外时序数据库；Python、前端依赖和 BaoStock 客户端版本通过锁文件固定。

回测引擎在阶段 0 按本文的账户、数据窗口和公司行动验收场景做选型：优先复用能满足语义的成熟 Python 引擎，必要部分由适配层补齐。选型结论、版本和限制先落文档，避免直接承诺自行重建完整交易所撮合系统。模型接口由本平台定义，保留引擎替换空间而不强求支持任意外部插件。

## BaoStock 接口覆盖范围

本方案以官方已发布接口为上限，规划完整覆盖；实际执行顺序按共享依赖和回填成本分阶段。各接口字段、日期范围和空值规则以官方 Python API/数据说明及连通性抽样为准。

| 官方数据族 | 规划接口/数据 | 平台用途与注意点 |
|---|---|---|
| 股票、ETF、指数 K 线 | `query_history_k_data_plus()`；`query_daily_history_k_AStock()`、`query_daily_history_k_ETF()` | 支持的日/周/月及 5/15/30/60 分钟；指数无分钟线。ETF 文档历史从 2026-01-05 起，分钟线起点存在口径冲突；日更接口的最早可查询日期需实测。 |
| 股票档案、历史证券池、交易日历 | `query_stock_basic()`、`query_all_stock(day)`、`query_trade_dates()` | 搜索、上市/退市信息、历史回测股票池和交易日驱动。历史股票池需按当日保存，减少幸存者偏差。 |
| 行业与指数成分 | `query_stock_industry()`、`query_sz50_stocks()`、`query_hs300_stocks()`、`query_zz500_stocks()` | 股票资料、行业筛选和指数成分视图。更新日期不自动等于历史生效日；实际历史查询和成分覆盖须验证。 |
| 估值指标 | 日 K 可返回 PE/PB/PS/PCF 等日频估值字段 | 个股估值曲线、列表排序与回测因子；页面显示字段频率、空值和数据日期。 |
| 公司行动与复权 | `query_adjust_factor()`、`query_daily_adjust_factor()`、`query_dividend_data()` | 复权行情、除权除息记录和回测现金流。分红登记、派息、红股上市日期各自处理，不按除权日统一入现金。 |
| 季频财务指标 | `query_profit_data()`、`query_operation_data()`、`query_growth_data()`、`query_balance_data()`、`query_cash_flow_data()`、`query_dupont_data()` | 六类指标从 2007 年起，但部分公司/字段缺失；按公告日和保守可用时间过滤，历史修订不等于原始发布版本。 |
| 业绩快报与预告 | `query_performance_express_report()`、`query_forecast_report()` | 快报从 2006 年、预告从 2003 年起；记录披露、报告期、更新字段，允许同报告期多事件。 |
| 宏观数据 | `query_deposit_rate_data()`、`query_loan_rate_data()`、`query_required_reserve_ratio_data()`、`query_money_supply_data_month()`、`query_money_supply_data_year()` | 浏览与导出全部支持序列；有可靠发布日期的数据才默认供历史因子使用。只有统计年月的货币供应量不能按月末假定已知。 |

以上覆盖当前 0.9.4 发布包导出的数据方法，各方法的实际查询结果见实施记录；一次成功调用不能证明所有证券、字段和历史区间完整。官网旧版本记录提到的其它接口（如 SHIBOR），若不在当前 SDK 导出和现行接口目录内，只登记为待核实，不能据旧记录承诺可用。资产类别/频率有不同字段，ETF 的空估值、ST 字段等不能直接套用股票语义。[官方发布包](https://pypi.org/project/baostock/) · [每日更新](https://www.baostock.com/mainContent?file=DailyUpdates.md)

## 产品功能规划

1. **市场总览**：以共同的最新完整交易日展示指数、市场行情摘要、涨跌统计和异动列表；区分股票、ETF、指数，展示证券总数/已更新数，不混用不同日期或部分市场数据计算排名。
2. **证券列表与筛选**：股票/ETF/指数搜索、个人自选列表与保存筛选条件；按代码、名称、交易所、行业、上市状态、行情和估值字段排序筛选，支持分页及稳定排序；历史回测使用当日证券池和状态。
3. **证券详情**：基本资料、上市状态、多周期 K 线/成交量；支持缩放、十字光标、复权切换和回测买卖标记。MA、MACD 等指标由本地数据计算并注明算法；财务、公司行动和业绩报告独立展示，未知字段显示缺失而不补造数据。
4. **行业/指数/宏观页**：行业分类与支持的指数成分查看；利率、准备金和货币供应量历史序列及数据导出。
5. **数据管理**：提供官方接口目录与“接口→字段→数据表→页面/策略”映射；可见全量回填/增量任务、运行进度、最近成功日期、接口错误、缺失日期、记录数和重跑入口；网页查询只访问 PostgreSQL，批量拉取由单独任务完成。
6. **策略管理**：导入、检查、登记、启用/停用、版本切换、参数保存和历史运行记录；策略代码和参数在提交时固化，历史结果不随文件改写而改变。
7. **回测与结果**：选择策略、股票池、起止日期、基准、频率、资金和费用；任务支持进度、取消、失败日志和结果对比。展示净值/回撤、收益与风险、订单/成交、持仓、费用及无法成交原因，并可导出结果和运行配置。

## 采集、更新与容量

官方[访问规则](https://www.baostock.com/blacklist)明确限制每天 API 请求不超过 50,000 次，并禁止并发连接访问；冻结时长随当年限制次数增长。平台采用唯一的串行采集通道，同步任务、重试和分页共享请求预算，预留余量并在接近上限或收到限制响应时暂停。回测读取本地库可以并行，但不能各自再登录 BaoStock 下载。

采集流程为：按交易日和覆盖范围生成任务 → 串行登录/查询并迭代全部结果 → 校验字段、范围、空值与记录数 → 分块写入并记录修订 → 完成后发布可用数据版本。分块结果先归入未发布批次，页面和回测只读取已发布版本；版本发布与覆盖状态更新原子完成，避免读到同批新旧数据混合。SDK 使用进程级默认 socket，不能将多个结果迭代器交叉执行；重连、超时和失败在同一通道中处理。[官方 SDK 源码](https://files.pythonhosted.org/packages/66/61/8ad575eb83d4b22852a922e669bc13c9723675343e885b0040ab11a6a321/baostock-0.9.4.tar.gz)

- 日更优先使用全市场 A 股/ETF 日线和当日复权因子接口；历史回填比较按代码/区间与按日期批量两种方式，依据实际最早覆盖日期、请求量和效率选择，不预设批量日更接口覆盖全部历史。
- 返回空结果可能是尚未更新、非交易日、未上市、已退市、该类型不支持或查询失败，需分别记录。`query_all_stock(day)` 在当日闭市后数据就绪前可以返回空，不能据此删除证券池。[证券元信息](https://www.baostock.com/mainContent?file=StockBasicInfoAPI.md)
- 读取全部分页后再排序/筛选；核对末次错误状态和覆盖范围，分页中断或部分写入不能标为全市场完成。写入按代码/区间或合理批次提交，失败保留已验证部分和断点，不按日期先删除全市场旧行。
- 缺口校验结合交易日历、上市/退市、停牌和接口覆盖；停牌不等于数据丢失，零成交量不等于可成交。异常价格、字段变化和类型转换失败进入异常记录，不静默丢弃或将空值全改成 0。
- 增量除追加新日期外，对最近区间回看并对官方数据调整记录涉及范围重取；财报快报需关注更新日期。相同内容幂等，内容变化产生修订记录。
- API 列表按页读取，图表按证券/区间读取，回测按固定版本批量读取；避免每个 bar 单独查询数据库或一次向网页返回整个历史库。

官方公布的更新时间均按北京时间处理，并留安全余量、检查真实就绪状态。计划时间不是成功证明；任务需要记录预期日期、实际成功日期及下一次重试。

| 数据 | 官方就绪时间 | 调度要求 |
|---|---|---|
| 日线 | 交易日 17:30 | 按交易日增量，股票与 ETF 分别核验 |
| 复权因子 | 交易日 18:00 | 依赖因子的回测待行情与因子都就绪 |
| 分钟线 | 交易日 20:00 | 作为历史分钟回测数据，不能用于 BaoStock 盘中实时信号服务 |
| 其它财务报告 | 交易日的次一自然日 01:30 | 区分自然日/交易日，按实际公告和修订范围更新 |
| 官方周线 | 周六 17:30 | 不承诺每个交易日都有本周最终周线 |
| 官方月线 | 每月 1 日 17:30，上月数据 | 不把完整月线提前用于月内信号 |
| 指数成分 / 行业 | 成分为周一下午；行业为每周一 | 记录接口返回的更新日期，历史生效日另核验 |

来源：[平台介绍](https://www.baostock.com/mainContent?file=home.md)、[行业分类](https://www.baostock.com/mainContent?file=stockIndustry.md)。本机休眠、关机或错过排程后，启动工作进程应按数据库水位补跑；同类任务去重，避免重复启动采集连接。

容量在实施获准后用样本测算，分别记录行数、表/索引/修订占用、请求数和耗时。仅作量级示例：5,000 个标的 × 每天 48 根 5 分钟 bar × 每年 250 个交易日约为 6,000 万行/年；这不是已验证的证券数或覆盖承诺。叠加所有分钟频率和多个版本会更大，因此先完成全市场日线，分钟线先按选定股票池/区间回填，后续按容量扩展。所有频率均规划接入，避免未经测算立即重复保存全市场每一种频率。

日线、周期线和分钟线分别存储；分钟大表根据测算按时间分区，日线先用证券/日期索引。若从 5 分钟或日线派生其它周期，需核对交易时段、午休、bar 时间定义和聚合口径，并标记“本地派生”、算法版本及已完成/未完成状态；官方序列与派生序列不静默互换。

## 数据模型、版本与历史可用时间

| 数据层 | 规划内容与关键约束 |
|---|---|
| 证券与日历 | `instrument`、`trade_calendar`、`universe_snapshot`、行业/指数成分记录；主键保留完整代码如 `sh.600000`，不能仅用六位数字或凭首位数字判断市场/类型。当前上市状态不得直接作为历史筛选条件。 |
| 行情与公司行动 | 原始日线、周期线、分钟线、日频估值、复权因子、分红事件；未复权数据为基础，重复键包含证券/频率/时间。公司行动按实际事件去重，允许一年多次分红，`report` 与 `operate` 查询不能导致重复派息。 |
| 财务与宏观 | 按六类财务指标和快报/预告分表保存来源字段、报告期、披露/更新日期；宏观保留统计期、发布字段和单位。空值、非数值文本和不适用字段不强制转换为 0。 |
| 版本与任务 | 数据版本、已提交修订、接口覆盖、同步任务/子任务、异常记录；覆盖到代码/频率/时间区间，状态区分未采集、成功、部分成功、源不覆盖、预期无数据与失败。 |
| 产品与回测 | 自选/筛选配置、策略与不可变版本、参数配置、回测清单、订单、成交、持仓、净值及指标。策略源文件保存在本地版本目录，数据库登记路径/摘要与版本。 |

价格和资金保留来源精度，现金账本使用明确的十进制/舍入规则；成交量的股数/份数、金额人民币元、比率百分数等按字段字典转换。源字段名、单位、适用资产类型和空值规则在接口映射中登记。财务报告是该 API 的指标集合，不承诺完整三大报表、公司画像或所有同花顺字段。

ETF 的资产类型只说明它是 ETF，不能据代码前缀或名称猜测是否 T+0、涨跌幅或收益分配方式。开放回测前须核对具体产品类别、该时期的有效规则、报价档位、费用和公司行动覆盖，并将依据固定在运行清单。日更接口中的 `isST` 等股票字段不能直接解释为 ETF 风险警示；不适用字段保留源值并标注用途限制。

公司行动接口成功或返回空，不等于对应资产没有分红。若 ETF 的分红、份额折算等事件缺少完整来源，仍可浏览行情，但不能把价格收益回测标为含分红总收益。除权参考价变化用于发现缺口，不能据价格差倒推出权益登记日、到账日、每份实派金额或税率。必要的正式公告补充需保存来源、原件摘要与明确覆盖区间，报告列出来源差异；已知缺口在发布回测结果前停止。510300 的真实接口空返回与正式分红公告并存，证据和规则来源见[ETF 核验记录](research/etf-rules.md)。

**可复现需要保留旧值。** 仅保存 `sync_batch_id`、更新时间或数据摘要，不能在行情被覆盖后重建旧回测。建议采用“当前查询表 + 仅在内容变化时追加的修订记录 + 已提交的数据版本”；修订保留旧/新值和生效版本，支持按固定版本读取。每次回测固定各数据族的已提交版本、使用范围和覆盖摘要，随后更新不会改写它的输入。被历史回测引用的版本不能随清理自动删除；不要求为每个回测复制整个市场库。

必须区分以下时间：交易/统计期、公告日、历史可用时间、来源更新日期、实际抓取时间。今天下载的历史行情可以用于历史回测，但今天的抓取时间不能证明旧财报原值当年已知。

- 日/分钟线只向策略提供已结束的 bar；周/月线只在该周期完成及采用的数据就绪规则满足后可见。多频率对齐采用截止时点查询，不能把未来已完成周期数据向前填充；指标预热窗口位于回测开始前且不产生区间外交易。
- 财报、快报和预告按各自披露/更新字段处理。只有公告日期、没有具体时刻时，默认下一交易日开始可用；不得假定公告当日开盘或当日收盘前已发布。业绩快报更新字段要保留，不能将修订后的数值退回原披露日使用。[季频快报](https://www.baostock.com/mainContent?file=seasonExpress.md)
- BaoStock 当前回溯数据可能修订历史字段，即使有 `pubDate` 也不保证拿到了当时发布的原版。因此报告明确标为“依据公告日期过滤的当前回溯数据”，不承诺完整历史发布版本；从平台开始采集后才逐步积累实际修订版本。[数据调整记录](https://www.baostock.com/mainContent?file=modifyRecord.md)
- 有发布日期的宏观数据按日期及保守可用时间处理；仅含统计年月/年份且没有可证实发布时间的数据，默认只用于浏览，不能自动当成历史已知因子。货币供应量现行返回字段未列具体发布日期。[月度货币供应量](https://www.baostock.com/mainContent?file=supplyData.md)
- 行业/指数成分的 `updateDate` 与查询日期须实测核对，不自动宣称能重建任意时期真实生效的分类。历史证券池还需验证最早可查询日期、退市证券与更名，不根据日线 1990 年起点推断所有参考资料都从同日起完整。

历史证券池还需保存完整成员集合；只保留逐行修订可能把后来移除的成员重新读出。查询采用同日最后完整已发布快照，固定版本读取其名称/状态，未发布批次不可见。真实 `query_all_stock(2023-01-03)` 中有后来退市字样，名称不能视为当年简称或用于判断当时 ST；资料与页面保留回溯来源限制，不能声称已恢复完整更名历史。实施与证据见[历史证券池说明](historical-universe.md)。

复权序列用于指标展示/信号计算，原始价格与公司行动用于账户记账。展示可以采用最新前复权，但回测应按信号时点的已生效事件和固定归一基准计算，不直接把含后续事件的最新前复权序列喂给绝对价格阈值模型；算法需与官方样本及手算事件核对。[复权因子](https://www.baostock.com/mainContent?file=factorInfo.md) · [本地复权说明](https://www.baostock.com/mainContent?file=localdatafactorInfo.md)

## 回测执行与报告

基础账户为单币种现金、做多，不默认包含融资融券、卖空或杠杆。策略返回目标仓位，或返回选股结果后绑定明确的排序、资金分配、调仓与退出规则；选出股票列表本身不是完整买卖策略。

日线默认在 `t` 数据就绪后生成信号，下一个可交易日开盘模拟执行；分钟线在信号 bar 结束后使用后续 bar。回测引擎依次处理公司行动、持仓可卖状态、待成交订单、市场事件、估值和新信号，事件顺序及同一时点买卖优先级固定并记录版本。订单有效期以及未成交/部分成交后的撤单或顺延规则必须明确，不能默认无限期等待。

开盘撮合只使用开盘前已知信息和执行时的开盘价，不能提前使用当日最高/最低价或全天成交量决定开盘成交和仓位。若用整根 bar 模拟成交量限制或限价触发，应明确属于周期结束后确认的近似成交，策略不能在 bar 结束前读取该成交结果。

- 分别记录现金、冻结金额、分红应收、总持仓与可卖数量。A 股卖出需处理 T+1；ETF 按具体产品类别确认是否可当日回转。买卖数量、价格档位、最小费用、涨跌幅、IPO/风险警示/退市等规则按市场、板块、资产类型和历史生效日期管理，不能对所有证券固定套一组规则。
- 成本拆分为佣金及最低收费、印花税、过户等适用费用和滑点，按买卖方向、资产类型及历史日期配置并保留来源；不能仅用一个固定总费率代替所有历史区间。分红税费另外列入账户现金流。
- 历史规则查官方交易所并保存来源和生效区间，实际实施与暂缓实施条款分开。当前沪深规则均有 2026 年修订及生效日期，不能把现行规则直接覆盖此前回测。[上交所规则](https://www.sse.com.cn/lawandrules/sselawsrules2025/stocks/exchange/c/c_20260424_10816482.shtml) · [深交所规则](https://www.szse.cn/www/lawrules/rule/stock/t20260424_620190.html)
- 科创板/创业板扩展先按[交易所原件核验记录](research/growth-board-rules.md)实施成熟上市样例。科创板申报最低 200 股、逐股增量，不能简化为 200 股倍数；创业板买入按百股倍数，零股清理、申报方式对应上限及 ST 单日累计限制另行处理。两板普通/ST 的 20% 与 IPO 前五个交易日无涨跌幅分别建模；2023-04-10、2026-07-06 的版本清单随运行冻结。缺盘口的日线/分钟近似不能宣称验证价格笼子或真实市价申报。研究完成后仍须逐项核对资金预算、目标订单、部分成交、公司行动和旧归档重算，才能开放对应资产；成熟上市样例不代表 IPO 或退市整理撮合已验收。
- 撮合考虑停牌、零成交量、资金/可卖数量不足、费用与滑点、价格边界、成交量参与上限和部分成交。OHLC 只能支持近似成交；一字涨跌停、bar 内触发顺序和排队不可由“价格曾触及”证明成交，采用保守约定并在结果展示假设。缺少必要规则/数据的标的明确跳过或停止任务。
- 股权登记确认分红权益，除权时确认相应应收权益，派息日入现金，送转股按生效和可交易日期处理权益及数量；分红税费假设单独记录。源税后字段可含多种值，不能无条件当单一数字；复权收益与账户现金分红不能重复计算。配股、合并等特殊事件若缺少可核实的必要字段，明确限制该段回测并停止或标记，不能声称分红接口已覆盖所有公司行动。[除权除息字段](https://www.baostock.com/mainContent?file=dividInfo.md)
- 同日多条分红还可能是原实施公告与更正版。正式公告版本、独立分红组成与摊薄除息金额必须分开；未知金额冲突停止发布或账本，不能直接相加、择大或认定较后抓取的行更有效。禾川科技真实案例两条源金额为原版 0.11 / 更正版 0.11038，最终虚拟除息现金另为 0.10990；源实施日期均为 6 月 7 日，不能据此识别 6 月 8 日更正。资料可以保留已核验的不同源身份，但回测仍须核验该资产规则、公告可用时点、最终权益及参考价。[核验记录](research/hechuan-2024-corrected-dividend.md)
- 停牌期间可沿用最后价格估值并标记，但不成交。缺失交易行情不能自动伪造成零涨跌。退市或回测结束未平仓有明确结算策略；缺少可执行退出价时保留未平仓/未解决状态，不以最后收盘价假装已卖出。
- 输入缺少必要因子、预热不足或基准覆盖不足时，任务说明缺失并按登记政策失败/跳过；禁止静默把缺失信号改成买入/持有。策略排序的并列项有稳定次序，随机模型保存种子。

每次运行固化策略文件摘要、环境/依赖、引擎与规则版本、参数、资金、数据版本、股票池与筛选时点、频率、交易成本、随机种子、基准和缺失处理政策。用户改参数或更新策略时创建新运行，不覆盖旧报告。

报告至少包含净值、总收益、年化收益、最大回撤、波动率、Sharpe、换手、费用、成交与未成交原因、持仓与样本覆盖。指标列出计算口径、无风险利率、计费与年化方式；分钟回测同时提供按交易日采样的风险指标。无交易/零方差等情况下未定义的指标显示为空并说明原因。基准与策略使用同一交易区间、日历和净值起点，注明基准为价格指数还是含分红收益序列，并随超额收益显示比较口径。

参数/模型对比使用相同数据版本和交易规则；保存参数选择区间、验证区间与独立样本外区间，避免把全区间调参最高收益直接当作验证结果。大批量参数任务仍走队列和资源预算，不要求首个版本加入自动机器学习训练平台。

## 模型安装与运行契约

先支持从受信任的本地目录导入 Python 策略包；网页导入 ZIP 若需要，作为同一安装流程的入口扩展，导入文件不立即执行。首个示例采用 `on_bar(context)` 返回目标权重的接口，具体契约见[策略接口](strategy-contract.md)；外部模型按实际样例适配。

| 项目 | 契约 |
|---|---|
| 清单 | 模型 ID、版本、平台接口版本、Python 入口、参数定义、依赖、频率、必要数据字段和预热长度 |
| 输入 | 截至当前模拟时点的历史窗口、历史证券池、账户/持仓状态、已校验参数；平台不向策略提供管理员凭据 |
| 输出 | 目标仓位或候选排序；若是候选排序，运行配置必须补足调仓和退出规则 |
| 安装与版本 | 检查接口/依赖兼容性和入口，登记文件摘要，保存不可变版本；停用/卸载保留已有报告引用的版本，不自动升级历史运行 |
| 执行 | 独立进程执行、日志/进度/超时/取消与失败记录；最初限制同时运行数量，避免占满本机资源 |

运行前锁定依赖，回测中不临时联网安装软件包；遇到依赖冲突先判定兼容性，确有需求再采用独立环境。独立进程用于故障和资源隔离，不宣称能安全执行未知 Python 代码。若用户模型是公式、已有回测框架类或机器学习文件，先验证适配方式，再扩大接口范围。

## 分阶段实施与验收

先交付可用的“行情查询 → 模型 → 回测 → 报告”完整流程，再扩大数据覆盖和频率。官方接口覆盖目标保留，分钟线全市场回填、宏观页不能成为首次验证核心流程的前置条件。任务日志、失败恢复、数据版本和基础测试从首个流程就纳入，不留到最后补。

| 阶段 | 交付 | 验收标准 |
|---|---|---|
| 0. 获准后做准备验证 | 检查环境及目标库；初始化数据库/迁移与应用角色；完整接口目录、样本字段与范围、费用/规则来源、引擎选型和容量测算 | 文档/SDK 声明与实际返回分开记录；每个接口映射到用途、表和覆盖状态；确认首个回测契约及性能基线 |
| 1. 首个日线完整流程 | 小股票池、指数基准、原始日线/证券池/公司行动、版本化入库；股票图表和一个明确标为示例的策略回测报告 | 入库后读回对照来源；订单、费用、T+1、分红与净值可手算核对；更新源数据后旧版本回测仍可复现 |
| 2. 日线平台与模型管理 | 全市场日线增量/回填、参考资料与估值；市场列表/自选/筛选/详情；本地模型安装、版本/参数管理、任务和结果对比 | 回填可续跑且受请求预算约束；部分更新标识准确；经典示例完成独立安装、取消、重跑和导出；用户提供其它模型后另行核验适配 |
| 3. 全部基本面与低频接口 | 六类财务、快报/预告、行业/指数成分、全部宏观接口及相关页面 | 日期/修订规则与缺失覆盖可见；缺少发布历史的数据不自动获得可回测标签；每个现行方法有支持状态 |
| 4. 多周期与分钟/ETF 回测 | 官方周/月线、支持的分钟周期、局部到逐步扩大分钟数据；验证后开放 ETF 对应回测 | bar/周期边界、未完成周期、资产交易规则和公司行动均核验；明确 OHLC 成交近似；回填规模符合磁盘/配额预算 |
| 5. 整体使用与恢复验收 | 查询/回测性能、参数样本外比较、中文使用说明、本机启动、调度补跑、备份与恢复演练 | 完整使用流程可复现；没有静默数据缺口/时间泄漏；备份恢复后仍能读取指定模型、数据版本与报告 |

每阶段交付后更新接口覆盖矩阵：已验证并可用、部分覆盖、待验证、源不支持四类，完整度按字段/证券/日期范围展示，不仅按实现了多少方法计数。性能基线用本机真实配置与代表性区间测量，包含列表首屏、十年日线图、单证券分钟图和多证券日线回测的耗时/峰值内存；在样本测算前不承诺秒级全市场分钟回测。

首个双均线模型不依赖财务或宏观数据，阶段 1 可以独立完成。后续模型若需要财务、业绩或多周期数据，在其接入前补齐必要接口并验证历史可用时间，再完成后续阶段的全面覆盖。财务历史回填也需按证券、年份、季度和方法估算请求预算，优先覆盖模型所需区间，不能把“全部接口接入”解释为所有历史立即下载完成。

## 本机运行、备份与检查

- 提供 PowerShell 启动/停止入口、依赖锁文件、配置示例、数据库迁移和中文操作说明；服务默认绑定本机地址。管理操作校验允许的 Host/Origin 和请求来源，运行账户不使用管理员权限。
- 离线补跑按各数据族已发布水位及每个证券/频率分别安排，从最早欠缺日开始分批，不能先取末尾一批再把早期积压越过。首次无水位仅取最新就绪日；水位之前的缺口仍需区间回填。任务去重、失败重跑与就绪门槛分别验收。[补跑实施与证据](scheduler-catchup.md)
- 同步与回测任务有持久化进度、心跳、运行器版本、取消和超时状态。进程中断不会留下永远“运行中”的任务；部分结果不伪装成完成报告，重跑不会重复发布结果。
- 日志记录接口、证券、区间、错误码和修复线索，避免记录凭据。更新状态包括数据时点、源就绪/请求限制/网络失败原因及下一次尝试，而不是仅一条成功消息。
- 长区间图表采用分段加载或明确的展示聚合；回测仍使用原始选定频率数据。筛选条件和报告数据可以导出，版本、单位与算法说明随结果保存。
- 本地备份覆盖 PostgreSQL 数据/修订/迁移、自选配置、策略不可变版本、依赖锁文件和恢复说明。清理或卸载前检查报告引用，不能删除仍需复现的数据/策略版本。以恢复后的实际查询和指定回测验证备份，文件存在或备份日志成功不等于可恢复。

实施阶段的必要验收场景：

| 场景 | 需要证明的行为 |
|---|---|
| 分页、断线、重复同步与字段异常 | 未发布批次对页面/回测不可见，不发布部分全市场数据为完整；续跑不重复、不删其它证券旧数据；异常保留证据 |
| 上市/退市、更名、停牌与缺口 | 历史股票池准确或明确标为受限；停牌不能成交，缺失不能伪造价格 |
| 数量/现金、T+1、成本及部分成交 | 可卖数量、费用舍入、资金余额、订单有效期与手算结果一致；开盘成交不使用当天未来量价 |
| ETF 产品分类、精度与权益 | 产品类别有明确依据；报价档位与现金舍入分别处理；股票税费/ST 字段不误用；实际分红登记/除息/到账一致，未知事件不以空结果代替 |
| 分红/送转与前后复权 | 权益、现金到账和可交易数量按正确日期处理；不重复计收益，不使用后续复权事件 |
| 财报/快报修订、宏观缺发布日期 | 日期可用规则生效；修订版本/近似等级可见；不能靠统计期推断当时已知 |
| 周月/多频率与预热 | 未完成周期及未来 bar 不可见；跨午休聚合正确；预热不产生区间外交易 |
| 数据和模型更新、取消与恢复 | 固定版本的结果一致；不兼容模型在运行前报错；取消/中断记录真实状态；恢复后引用仍可用 |
| 指标与基准 | 净值含费用/现金流；年化与采样口径固定；未定义指标不捏造；基准区间与收益类型明确 |

## 范围与剩余设计决策

- 数据接口接入目标是全部现行官方方法；实际市场/字段覆盖受源限制，源没有的数据不能通过程序“补齐”。不将当前 SDK 未导出的旧接口或元数据中的证券类型视为已支持行情。
- 当前覆盖不包括实盘、实时/逐笔/盘口、新闻全文、机器学习训练平台。若之后用户要求这些，再增加来源和相应模块；分钟历史回测不等于 BaoStock 能提供盘中分钟信号。
- 历史修订无法完全逆推出首次发布的原值，OHLC 无法重建真实排队成交；报告保留这两类实质限制，不能宣称完全无偏差或实盘等价。

还需在对应实施阶段确定的输入（不阻碍本次方案修订）：

1. 首个模型已确定为平台提供的经典双均线 Python 包，不再等待用户提供样例。后续若接入用户自己的公式、回测框架或机器学习模型，再核验真实文件、依赖和数据频率；网页 ZIP 入口按实际需要扩展。
2. 初始历史年限与分钟股票池：按首个模型数据需求、接口验证和磁盘测算定稿，不默认立即全市场全频率回填。
3. 本机 PostgreSQL/运行时版本、可用磁盘与内存已初步核验并记录；后台常驻条件、完整容量/性能基线及扩展引擎规则继续按实施阶段核验，已完成项以实施记录为准。
